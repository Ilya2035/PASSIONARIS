# Архитектура ORBIS

## Почему не движок Europa Universalis V

Движок Paradox (Clausewitz/Jomini) закрытый: на нём можно делать только моды к их играм, но не свою отдельную игру.
Поэтому у ORBIS свой движок: **Three.js (WebGL2) + Electron**. Методы Paradox мы повторяем идеей, а не кодом:
карта как растр «клеток» с таблицами поверх, раскраска режимов карты через таблицы цветов, границы в шейдере.
Ассеты EU5 не используются — только открытые данные (см. `data/ATTRIBUTION.md`).

## Слои данных карты

```
участок (атомарная клетка растра)  →  район  →  провинция  →  страна
```

* **Участок** — пиксель растра `cells` (сейчас 8192×4096, ≈4,9 км на экваторе). Цель — **1×1 км**.
  Игрового смысла у участка нет: это «кирпичик», из которого собираются районы.
* **Район** — игровая единица (там будут кварталы, здания, население). 74 091 район в v0.1.
* **Провинция** — административная единица (Natural Earth admin-1, 4 603 шт.).
* **Страна** — Natural Earth admin-0 (258 шт.). Позже: страна = владелец района на дату.

Растр `cells` хранит **id района**; всё остальное — таблицы (`world.json`), поэтому смена владельцев,
режимы карты и эпохи не требуют перерисовки растра.

## Глобус

* Сетка — полярная, с центром под камерой; кольца распределены как `a·sinh(t·b)`: детали сгущаются под камерой,
  при этом всегда рисуется вся планета.
* «Разворачивание»: глобус радиуса 1 переносится на сферу радиуса `1/c`, касающуюся его в точке фокуса.
  Длины дуг от центра экрана сохраняются → в центре искажений нет. `c = 1` — глобус, `c → 0` — азимутальная карта.
* Камера: фокус `F` + «верх экрана» `U`. `U` медленно тянется к северу (τ = 0,55 с, ≤110°/с) —
  при пролёте над полюсом экран плавно разворачивается.
* Границы: «билинейное большинство» по 4 соседним участкам + аналитическое расстояние до изолинии →
  гладкие линии постоянной толщины в пикселях на любом зуме.

## Новая схема карты (решение от 2026-11-09, обновление 0.2 «Природная карта»)

Заменяет деление по современным админ-границам (оно в v0.1 — временное).

1. **Природные области.** Суша делится по географии, а не по политике и не по городам:
   территории **между реками** (например, от Рейна до соседней реки), **горные массивы — отдельными областями**,
   **озёра — отдельно**. Каждая область подписывается (междуречье, массив, плато, равнина).
2. **Морские зоны.** Мировой океан — ровные участки, примыкающие к прибрежным областям; их много.
3. **Куски ~100 км²** (сетка ≈10×10 км) внутри природных областей: реки проходят **по краям** кусков
   (Орлеан делится Луарой посередине), в каждом куске со временем — свой городок. Это ~1,3 млн кусков на суше,
   поэтому рисуются они процедурно, в шейдере, без тяжёлых текстур.
4. **Политический слой поверх.** Куски дорезаются по историческим и «логическим» границам так, чтобы из них
   собирались реальные земли: Мозель, Рейнская область, Бельгия в нынешних границах и т.п.
5. **Графика.** Простая и красивая, процедурная (перерисовывается каждый кадр), чёткая при приближении
   до масштаба ~2 км — вместо размытой фотоподложки.

## План: участки 1×1 км (заменён схемой выше: базовая сетка ≈10×10 км)

Глобальный растр 1 км ≈ 40 000×20 000 — в одну текстуру не влезает. План:

1. **Тайловая пирамида** (как у веб-карт, но на кубосфере, чтобы участки были почти квадратными и равными по площади):
   уровни 5 км → 2,5 км → 1,2 км; тайлы 512×512 подгружаются по мере приближения (виртуальная текстура).
2. Высоты 1 км — AWS Terrain Tiles z7–z8 (≈0,6–1,2 км), запекаются тем же `bake-map.mjs` по тайлам.
3. Цвет поверхности — Blue Marble 21600 (1,85 км) тайлами; позже — Sentinel-2 / ESA WorldCover для типов земли.
4. Районы режутся на 1-км сетке: плотность районов зависит от населения (WorldPop / GHSL), в городах районы мельче
   (Париж — десятки районов), в пустынях и тайге — крупнее.

## План: границы всех эпох (обновление 0.3)

Задача: чтобы из районов можно было собрать **самые распространённые границы всех государств** за всю историю.

1. Собираем исторические границы из открытых источников с подходящей лицензией (проверяется для каждого набора:
   например, `historical-basemaps`, CShapes, Thenmap — у части наборов некоммерческие или «вирусные» лицензии).
2. Накладываем на современные провинции все исторические линии → провинции режутся так, чтобы каждая историческая
   граница проходила по краям районов (провинции = «общий знаменатель» всех эпох).
3. Слишком мелкие осколки сливаются с соседями, если граница встречалась редко (порог по «популярности» линии).
4. Для каждой эпохи хранится таблица «район → владелец», а не отдельная карта.
